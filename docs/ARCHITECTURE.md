# Architecture in detail

The long description of each module, moved out of CLAUDE.md so it isn't read in every session. Read the part you need before working on a module. The code and its doc comments are the source of truth: if this file disagrees with them, trust the code (and fix this file).

## Asset scripts

- `npm run card-art -- images/<name>.png [maxWidth]`: make a card painting, `src/assets/cards/<name>.webp` (480px wide unless `maxWidth` says otherwise), from a large original PNG or JPEG; name the original after the card's template id (`images/medic.png` for Médico) and the card shows it with no code change (`CardArt`'s `PAINTINGS`, checked by `CardArt.test.tsx`); an image without transparency (any JPEG) has its drawn-in checkerboard background removed, or its white background faded out when its border is all white, or a flat darker grey background (its border all one colour) taken out with a thin soft edge. The originals live in `images/` at the root, which git ignores
- `npm run mix-paintings -- <left> <right> <out>`: a painting for an action with none of its own yet, from two in `src/assets/cards`: each trimmed to its drawing and set side by side, standing on the bottom edge (`explosives-mix` for the Explosives fire option)
- `npm run icons`: regenerate the app icon PNGs from `public/icons/icon.svg`
- `npm run add-scenario -- [--check] [--replace] <file>`: add a map exported from Mis mapas ("Exportar", `<id>.m44map.json`) to the catalog, so every device has it once a push to `main` deploys it. It loads the app's code through Vite (`runnerImport`), checks the file (`catalogFile` in `data/catalog.ts`: `parseScenario`, not a built-in's id; `--check` stops there), writes `src/data/catalog/<id>.json` as exported (id, terrain and units unchanged, so a game in progress on the device's copy goes on with the catalog's; `formatJson`; `--replace` updates one already there, keeping its `notes` if the file has none), adds it to `scripts/boards.json` and paints its art with `npm run board` (with `"drawn": ["river"]` when no river tile fits a bend). A map bigger than 13×9, or with a river fork no tile fits, isn't painted: its entry and image are removed and the app draws its art, as for Mis mapas. The description, `notes` and tests for special rules are added by hand
- `npm run board [-- <part of a name>]`: build the scenarios' board art from their terrain, every board listed in `scripts/boards.json` (its terrain file in `src/data/boards/`, which `scenarios.ts` imports too, or a catalog scenario's file, whose `tiles` and `pickedTiles` it reads, standard boards only; the image to write, `drawn`: terrain to draw in code instead of painting it, `river` (with its bridges; hedgerows and lakes are always drawn), and `separateHills`: each hill on its own tile instead of joined into ridges). The base is the empty board (`scripts/board-art/empty-board.webp`, its grid measured at the top of the script) cropped to the edges of its hex grid, the box the app lays the image in, built at its full size (2435×1514) and saved at the app's (1621×1008, `APP_ART_HEIGHT`). Painted terrain comes from the tile library, `scripts/board-art/tiles/<terrain>/`: one hex per image, filling its width, at any resolution; each hex gets one of its terrain's tiles, turned 60° a random number of times (seeded by the hex). A river tile's name starts with the edges its river joins (0 = east, clockwise: `3-0.webp` runs west to east, `0-2-4.webp` forks, `3.webp` ends in a pond): a river joining three river hexes forks, one joining one runs into a lake beside it, else ends in a pond if it stops on the board, else carries straight on, the first a tile fits (`riverPlanner`). A lake is painted from `tiles/lake/` (named by the edges its water carries on through, `-r<edges>` for a river flowing in: `0-1-5-r3.webp`) when every hex of it has a piece that fits, and drawn otherwise. Water tiles have no grass or bevel of their own, only the water and a narrow bank (`npm run water-tile -- <tile> <library tile>` makes one from a whole hex). A beach (`tiles/beach/`) and a swamp fade out along a ragged line into the land beside them (`JoinedHex.fade`), a beach tile whose name starts with edges (its grass tufts there) turned to face it, or one named `surf-<edges>` turned to face the ocean beside it. An ocean hex (`tiles/ocean/`) next to land takes the tile whose shore best faces it (`4-5.webp`: the land across edges 4 and 5, `tilesFacing`), else open sea (`sea.webp`), only turned 180° so its waves stay level. By about one in three of a forest's edges onto the countryside, a lone tree or two stand out on it (`SPILLS`, a `spill` hex laid over everything else, `spillMaker`) and it's turned to join the river's edges; a painted bridge is a river tile with `board-art/pieces/bridge.webp` laid across it. A hill is made into a ridge (`scripts/joined-hills.mjs`): the plateau runs out through each edge it shares with another hill or a river (the lakes' outline, `shoreCurves` in `src/boardArt/terrainTiles.mjs`, with a wider neck, bulging only a little way into a river), the hill tile's cliff ring is unrolled along it, the plateau is laid across the whole board so it carries over the hex lines, and a little past the cliffs' foot the hill is clear, so the board's countryside shows round it; a lone hill is made the same way. Forests and hedgerows next to their own kind blend into it (`src/boardArt/joinedTiles.mjs`): on each shared edge the tile's bevel is replaced by the tile mirrored in from just inside it, with a faint hex line, and a forest grows tree crowns (cut from the tile, found by their lit middles) across it, the same crowns drawn by both hexes. Every town has its tile's houses lifted off (on the official tile found by their blue-grey roofs; on the others drawn round by hand in `<tile>.json` beside it, `HouseOutlines`, points in the tile's pixels; a main building too big to move, a church or a barn, stays where it is), the ground under them filled from the tile turned or mirrored, and laid out again by the hex, round a cobbled square near the middle and along a main street across the hex (along its first street out, if it has one), which the houses are kept off, so they stand apart; its streets out start at the square. A town's tile is picked by the hex, or in the map editor (`Scenario.pickedTiles`, planBoard's `picked`). Out over open countryside (`bare` edges, a town's, a river's or a hedgerow's countryside included), a forest grows more crowns, one town in two has a house standing partly over one such edge (`spill`), a town's streets run out a little over an edge or two (`streets`, always towards a bridge), and its cobbles spill over some edges in lumpy yards: an overflow image half as large again as the hex, laid on last. Towns and rivers (painted ones through the same maker, drawn ones after they're drawn) end in the board's countryside: their tile's grass is kept only near the cobbles, houses or water, out to a wandering edge, and is clear beyond (`toCountryside`); each neighbour reaches into a river hex only by the edge it's next to: a forest (`woods`) grows in up to the water in the part of the hex facing it (`growWoods`), each tree whole (kept clear of the water and the hex's edge); a hill (`hillShapes`) runs on in as its own outline drawn from where it is (`hillOver`, `growHill`), its cliffs closing short of the water; a town's yards and streets and a hedgerow's fields spill over that edge too. Hedgerows are always drawn (`terrainTiles.mjs`): fields and hedges in a rounded patch, the shape a lake's shore is made with, running on into the hedgerows beside it and spreading past the hex onto open countryside (`bare`), an image `HEDGEROW_SPREAD` times the hex's box laid on after the hex lines are softened. The bridge piece is laid at `BRIDGE_WIDTH` of its width. Lakes, and drawn rivers, bridges and hedgerows, come from `src/boardArt/terrainTiles.mjs` (a river flowing through the edges it shares with the next river or bridge hexes, a lake joining its lake neighbours); the board's edges are made soft (`src/boardArt/softLines.mjs`; it also grades the empty board's pale print into a darker, fuller green first, `gradeCountryside`, so the app's `empty-board.webp` is graded too): the empty board's dark frame round the grid is filled with the countryside beside it (mirrored out across the edge hexes, so a map ends in countryside; the app's `empty-board.webp` has it too), and the hex lines (printed, and the tiles' rims) are blended with the board mirrored in from just inside each hex so 30% of the line is left, and the frame round the grid is put back over the new hexes. The barbed wire and sandbags pieces aren't part of the board art (they change in the game): they're `src/assets/pieces/*.webp`, drawn on the hex by `BarbedWireArt` and `SandbagsArt`, each image the hex's box with the piece where it sits. The terrain carries on into the half hexes just outside the board that the art's box shows (the zigzags above and below, the ends of the short rows: `outskirtKeys`, keys like `-1-4`), so a forest or a river doesn't stop dead at the edge: planBoard's `outskirts` gives each the terrain most of its board neighbours have and runs a river on through the edge it flows out of; nothing of them comes back onto the board (no lone trees, houses or streets), the frame is kept off them, and they're only art (nothing can stand there). Which art each hex gets (tile, turn, river edges, lake edges, ridges) is planned in `src/boardArt/boardPlan.mjs`, shared with the app; the script also writes the app's smaller empty board, `src/assets/board-art/empty-board.webp`

## Modules

- `src/game-core/`: plain TypeScript game logic with **no React imports**:
  - `BoardManager`: hex grid (with `bothSides`, both sides' units and every sandbag, for the map editor), Axis flip, pathfinding (`calculatePossibleMovesWithPaths`; a hedgerow is only entered from the hex the move starts on, and a unit leaving one moves 1 hex)
  - `Hex`: its terrain (`getType`, and `getTerrain`, the terrain's rules from `data/terrain.ts`; on a map with `Scenario.fordableRivers` a river's rules are `FORDABLE_RIVER`: any unit wades in and stops, can fire with `FORD_FIRE_DICE`, `FireContext.fromFord`, and is fired at as in the open; the editor's "Ríos vadeables" switch, `setFordableRivers`), barbed wire (`wire`, from `Scenario.wire`: removable, so not a terrain type; it stops any unit that enters, and a tank that enters removes it, `WIRE_CLEARING_UNIT_TYPES`, kept as `Order.clearedWire` or on the take-ground move for undo), sandbags (`sandbags`: this side's units' only, from `Scenario.sandbags` and Fortify; the enemy's can't be known, so firing asks. `GameSession` clears them when the unit moves off, keeping them on the order or battle edit for undo), board section (`_setSide`), neighbors (offset↔axial coordinates)
  - `GameSession`: owns one player's game (board, command and combat decks and hands, coins, turn flow) and is the only place game rules run. Actions (`dropUnit`, `undoDrop` and `finishParadrop` for a scenario's paradrop (PARADROP, before the first turn: the player taps where each paratrooper landed on the table), `pickCard` (with the section, when `cardNeedsSection`) and `unpickCard` (back to the cards before any order is given), `issueOrder` (with an order slot, when a unit could take more than one), `undoLastOrder`, `commitOrders` (locks the orders and goes straight to MOVEMENT), `startBattle`, `endBattle` (which draws the command card), `drawCard` (only for an old save; a single card is kept at once; `drawAgain` swaps it once, Gamble; Probe draws 2 and `keepCard` keeps 1), `endTurn`, plus the map sync `removeUnit` (with the experimental `artilleryCrew` rule, `GameSetup.artilleryCrew`, a menu "Ajustes" switch, saved: artillery removed in the final phase leaves an infantry unit on its hex, `leavesCrew`, the edit's `replacement`), `relocateUnit` and `undoBattleEdit` (`canEditMap`: in the final phase, and in Órdenes before any order or mark, to fix a map that doesn't match the table; those edits are `beforeOrders` and can't be undone after the orders), `placeReinforcement` for the Reinforcements card (its unit, infantry, arrives on the cross as the final phase starts, with no roll; `placeReinforcement` when the cross was taken; the new unit is an `add` battle edit), and firing: `fireTargetsFor` (the hexes a unit can fire at), `fireAt` (at a hex picked on the map; `fire` takes the questionnaire's answers directly), `fireCollision`, `undoShot`, `canTakeGround`/`takeGround`/`undoTakeGround` (after a close assault with a hit or a flag, armour (never infantry) takes ground: it moves to the target's hex as a battle edit and gets one more shot, adjacent only; `Shot.tookGround`, derived in the summary), `keepResults` (apply fewer results than were rolled: `Shot.kept`, read with `appliedFaces`), `skipUnmovedFire`, `removeWire` (infantry on barbed wire removes it instead of firing: a 0-dice `Shot` with `removedWire`; firing from wire costs it a die, `WIRE_FIRE_DICE`; pass and play's `PassAndPlayMatch.removeWire`, and `settleWire`, which takes wire one side removed off the other's board (`wireRemovedByEnemy`) once the orders are carried out, after taking ground and after removing it) and `removeWireAt` (a map edit for wire removed at the table), `removeSandbagsAt` (a map edit taking sandbags off to fix the map), `fortify` (Fortify: in the battle, ordered infantry puts sandbags on its hex instead of firing, a 0-dice `Shot.fortified`, `canFortify`; pass and play's `PassAndPlayMatch.fortify`), the defensive cards (Ni un paso atrás's `ignoreFlags` and Blindaje personal's `ignoreHits` in pass and play's `sufferHits`, told the faces that hit, `armorHits`; Camuflaje's badge, `camouflaged`, kept from turn to turn until the unit moves or battles (`camouflagedUnits`, `isCamouflaged`; the enemy's camouflage: `EnemyUnit.camouflaged`, `ArmyView.camouflaged`, and the fire question `camouflage` when `enemyCamouflage`); Reposicionamiento and Tras las líneas enemigas (`MoveEffect.moveAfterBattle`) in pass and play's final phase, `finalMove`/`makeFinalMove`, one unit at a time (a `move` edit with `reposition`); Médico and Mecánico, given to a weakened ordered unit (`AssignRule.weakened`, known only in pass and play), whose `heal` effect `GameSession.heal` applies as the match carries out the orders, a figure's hits per figure, kept on `Assignment.healed`), `drawCard` also draws a second card straight into the hand in a side's first turns with `Scenario.extraDraws` (Pegasus Bridge's Axis; `extraDrawn`), plus `markCloseAssault` and `undoCloseAssaultMark` for the Close Assault card, `hasOrderedUnitFor` for a card with `CombatCard.needsOrdered` (Spotter does nothing without an ordered artillery unit: Órdenes warns)) return `false` and change nothing when they aren't allowed. After each change it publishes an immutable `GameSnapshot`.
  - `CommandCard`: a card's rules as data (sections, fixed or `"chosen"` on play; unit types; number of orders or `"all"`; `perSection` quotas; `onTheMove` extra units that can't fire; `noMove`, `moveBonus`, `maxMove`, `holdShots`; `coinCost` for orders paid in coins; `fireBonus` dice; `closeAssaultOnly` for a card with no orders whose units are marked in the battle; `drawChoice` for cards drawn in the final phase to keep 1 (Preparations: 2); `endOfTurnReward` for Preparations and Refuel; `rewardCard`, the card Refuel gives instead of the draw, from the cards kept out of the deck (`reserve`: Armor Assault, and a Direct from HQ for a side with no armour left; `GameSession` derives which are out, never shuffles them in, and puts them back out once played); `title`, the name on the card face, and `summary`, the few words on a tactic card's face). The house decks are in `data/commandCards.ts`: `commandDeckFor(scenario, faction)` builds a side's 24 cards, the shared ones plus 5 for the unit types it has; `GameSession.commandCards` and `combatCards` are the whole decks (the deck visualizer shows them, grouping copies by `templateId`). Card names follow the official Spanish edition where we found them (Batida, La Hora de la Verdad, …) and the English edition in English; a few are house names (Vanguardia).
  - `orderRules.ts`: the orderable units (no order yet, and an action they can be given) and `MoveLimits`. `actionRules.ts` (the actions mode): `actionRefusal` (why a unit can't be given an action: another type's, not on own tablets, morale 0 (only Morale Up), a supply or equipment it lacks, no ammo or shells for one that fires), `moveLimitsOf`/`moveRulesOf`/`shotsOf` from the action's data (`data/unitActions.ts`), `plainActionForMove` (`PLAIN_ACTIONS`: the action a plain move turns into, for `GameSession.issueOrder` and the computer), and the fire options (`fireOptionRefusal`, `plainFireOption`: a shot with nothing picked and what a collision spends, `canFireAShot`). `unitSupplies.ts`: a unit's supplies as values (`fullSupplies`, `pay`, `refund`, `reload`, `refill`, `endOfTurn`); `GameSession` keeps each unit's, pays the orders' costs in `commitOrders` and carries out what the actions and cards do there (`carryOut`: Reload, Morale Up, Fortify's sandbags, Medic and Mechanic in pass and play; `refillByCard`: Resupply, Refuel; Take Cover in `sufferHits`, Camouflage in `endTurn`, Behind Enemy Lines' move in `finalMove`; on own tablets the table does Medic, Mechanic, Take Cover and that move, `tableReminders`), takes a point of infantry's morale per flag in `sufferHits`, rolls every shot and collision with the unit's luck (`luck.ts`: `rollWithLuck`, one draw per die; card attacks roll without it), pays each shot's fire option as it's rolled (a `Shot` keeps its `option` and what it `spent`, given back by `undoShot`) and gives energy back in `endTurn` (more to a unit that rested). A unit with nothing left to fire has no shots left (`summarizeOrders`' `outOfAmmo`); the action's `fire.round` puts it in the firing order (Behind Enemy Lines `firesFirst`, No Respite with the units that didn't move).
  - `combatCard.ts`: the `CombatCard` type (cost; every card is played with the command card, up to `MAX_COMBAT_CARDS_PER_TURN` (2), never two copies of one (`templateOf`); an optional `marker` rule for hexes to mark on the orders map, checked in `markerRules.ts` and set with `markHex`/`undoMarker` (each card's marks in turn: one list, each card owning a span, `GameSnapshot.marking` and `markerKinds`); an optional `assign` rule for a card given to one unit while ordering (`assignCard`/`unassignCard`, `GameSession` keeps `Assignment`s by unit, saved by index; the unit has a card badge on the maps, `Board`'s `cardBadges`, and the card's name on its `FireOrderList` row; a camouflaged unit has `CamouflageIcon`'s badge, `Board`'s `camouflaged`), and an optional `tableReminder` for the final phase (own tablets only), an optional `battleReminder` for the battle's "Instrucciones", and an optional `effect` the app applies: `diceBonus` (added by itself to every shot of its unit type, or of the unit it was given to, as a card step: `combatBonusesFor`, `FireContext.combatBonuses`; with `face`, its dice aren't thrown but added showing that face, Fragor del combate's flag: `DiceStep.face`, `setFaces`, and `DiceResult`'s `placed` dice, there from the start), `firesWithUnmoved` (¡Fusiles arriba!: the moved infantry fires in the first group, `OrderSummary.unmovedGroup`), `concentratedFire` (Fuego concentrado: `joinable` lists the units that didn't move and can roll with the one firing; `FireChoice.joined` makes one roll with every unit's dice, each on its own die, `Shot.kinds`, `placed`; the lead shot has `joined`, the others `joinedTo`, all a `group` that "Anular disparo" takes back whole), `suppressiveFire` (Fuego de supresión: a per-shot switch, `FireChoice.suppressive`, rolls the `suppressed` die kind, `suppressive` or `longRangeSuppressive`), `attack` (rolled per marked hex with `attackHex`, before any unit fires; `attackMarks`), `move` (a "Usar …" toggle per move card when ordering, `Order.boostCard`, `boostedLimits` and `MoveRules` in the pathfinding), `changeSection` (Tactician)); no card is played as a reaction (Ambush, Out of Ammo, Pull Back, Out of Fuel and Shell Shortage were taken out in Step 61); the cards are in `data/combatCards.ts`, and `combatDeckFor(scenario, faction)` builds a side's deck from the scenario (each card's `DeckRule` has a `DeckReason`, kept on the card as `CombatCard.reason`, labelled in `DECK_REASON_LABELS` and drawn with `DECK_REASON_ICONS` (`GameIcon`; none for the shared cards) as a badge on the card and before its group's title in the deck; `combatDeckEntries` lists the deck with copies and reasons for the menu): 1 copy of each card the side gets (the shared ones; defensive cards for the defender; offensive ones for the attacker, with 2 of Sin tregua; the rest by its units, Rattenkrieg on a map with more than 8 town hexes, `Scenario.bigGuns` for Cortina de Fuego and `Scenario.airPower` for the air cards' copies). `GameSession` keeps the combat deck and hand (2 to start, at most 3): the cards are played with `pickCard` (`canPlayTogether`, and `combatCardFits`: Tactician needs a card for one section), paid then, and taken back with `cancelCombatCard` until the orders are confirmed (not one whose movement an order used); the final phase draws one with `chooseReward("combatCard")` or `drawCombatCard` (Preparations), and `discardCombatCard` when the hand is over 3. **Test mode** (`GameSetup.testMode`, the menu's "Modo prueba" switch, `GameSession.testMode`, saved): the hand starts with one of every combat card (`allCombatCards`), there's no hand limit, played cards come back to the hand at the end of the turn, and each turn starts with at least `TEST_MODE_COINS`
  - `ai/`: the computer player for a pass and play match (the menu's "Contra el ordenador", `MatchSetup.computer`; `useComputerPlayer` in `MatchView` plays its side at once outside the battle, and `SharedBattleView` drives it in the battle, one thing at a time after `COMPUTER_PAUSE_MS`, its shot up until the person taps "Seguir") ([docs/PLAY_THE_COMPUTER.md](docs/PLAY_THE_COMPUTER.md)): `aiStep(match, side, brain)` does the side's next action through the same session and match actions a person's taps call (`false` when it has nothing to do, or the step is one both players share: the reveal, the movement and collisions, ending the battle), and a `Brain` picks among the options, seeing the enemy only as a player on that side would (`seenEnemies`, from `opponentOf`); `basicBrain` is the very basic one, `standardBrain` the one the app plays (`makeStandardBrain(STANDARD_WEIGHTS)`: hexes scored by the shots they give against the fire they draw, terrain cover counted, the nearness of the enemy and of the objectives; shots by the share of the target they'd destroy; extra orders bought with supplies, `Brain.extraOrder`; combat cards from `combatCardChoice.ts`: the ones it knows, worth more than their supplies, with `Brain.markFor`, `assignTo` and Concentrated Fire's `joined`; a card no unit can take goes back to the hand). `selfPlay.ts` plays a match brain against brain for tests: `aiStep.test.ts` plays every built-in scenario without getting stuck, and `duel.test.ts` (only with `AI_DUEL=1`) counts the games one brain wins against another (`AI_TUNE=1` searches the weights)
  - `Unit` (`elite`, from `Scenario.elite`: a scenario's badge, drawn as a star; it moves and fires as its type does and carries more supplies), `Order` (its action's id, its shots; `canFire` is `shots > 0`; an order's index identifies it for the turn), `Deck`
  - `position.ts`: `samePosition`, `positionKey` ("row-col") and `includesPosition`; use them rather than comparing rows and columns by hand
  - `fogOfWar.ts`: fog of war in pass and play and against the computer (`MatchSetup.fogOfWar`, the menu's "Niebla de guerra" switch in Ajustes, on by default; `PassAndPlayMatch.fog`, saved with `sighted`): `inSight`, the enemy units a side's units see (`VISION` hexes, `VISION_FROM_HILL` from a hill, in line of sight, enemy units blocking it), and `seenHexes`, the hexes they see. The match works out each side's sight (`sightOf`): against the computer live from the move to the end of the battle (and the units that fired at it this turn, and in the battle the artillery ordered to fire), and frozen at the end of the battle (`sighted`) until the next move; none before the first battle, when both armies are known; between two people only in the battle. `fogOn(side)` is the fog on a map drawn from that side's board, `Board`'s `fog` (`OpponentContext`'s on the game screen's maps): the dark hexes (the person's unseen ones against the computer; between two people those either side doesn't see) and that side's units left off (those its enemy doesn't see, when the enemy is a person); the battle draws the computer's board with all the person's units (`opponentOf(…, { fogged: false })`). `opponentOf` keeps only the seen units (and their orders, sandbags and camouflage), so the maps and the computer (`seenEnemies`) know only those; `enemiesOf` marks the rest `EnemyUnit.hidden`, so they aren't targets (`GameSession.seenEnemies`, `enemyAt`) but still block retreats and moves, and an attack card hits them (`enemyAt(…, { hidden: true })`)
  - `boardSize.ts`: a board's size (`Scenario.board`, omitted for the standard 13×9; up to `BOARD_LIMITS`, rows always odd so the board turned round for the Axis keeps its long rows), `isOnBoard`, `boardPositions` and `sectionLines` (the left and right sections each about a third of the board, the border hexes in the short rows; `Hex` takes the board's width for its section). `turnedRound` takes the size. Bigger maps are played in pass and play (and against the computer) only for now: the menu offers no own-tablet game for one. Their art is drawn by `drawBoard.ts`: each hex one of the empty board's, picked away from its printed section lines, its frame stretched round them and the section lines drawn where the thirds meet
  - `scenarioDraft.ts`: the map editor's edits as pure functions on a `Scenario` (`paintTerrain`, `placeUnit`, `removeUnit`, `toggleElite`, `toggleSandbags`, `setWire`, `setObjective`/`toggleObjective` (a side's objective, one hex each, named "Objetivo N" until renamed), `clearHex`, `resizeBoard` (an edge grown or shrunk by a column or two rows, new hexes painted with a terrain, everything moved along; `BoardSizeDialog`): a new map, the same one when nothing changes, `false` when not allowed), `strokeOf` (what a tool does over one stroke of the finger, decided on its first hex), the scenario's settings (`setText`, `setAttacker`, `setHandSize`, `setAirSorties`, `setBigGuns`, `setExtraDraws`, `setParadrop`, `setVictory`, `setVictoryMedals`, `setObjectiveName`, `removeObjective`, within `SETTING_LIMITS`; air sorties and big guns are left out while both sides have the usual ones), `newDraft`/`copyDraft`/`newMapId`, ids (a map's id is its name's slug and a random part, `bocage-3f9k`, kept once the map has left the editor named: `slugOf`, `mapIdFor`; a new map is `map-` and the random part until then, `isProvisionalId`), and undo (`recordStep`, with `amend` for a stroke or one setting changed again, `undoStep`, `redoStep`)
  - `scenarioFile.ts`: a scenario as a plain JSON file (`ScenarioFile`, `toScenarioFile`; the format is described in `scenarioFile.schema.json`, kept in step by its test), what the map editor will save and the catalog keeps. `validateScenario` lists what keeps a scenario from being played (`ScenarioProblem`: a `Localized` message and its hexes); `parseScenario` reads unknown JSON or throws a `ScenarioFileError` listing everything wrong.
