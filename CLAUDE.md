# m44-sim

A companion web app for playing Memoir '44 with **simultaneous** turns, using a loose house variant rather than the official rules. Each player runs the app for their own faction next to the physical board. They pick a command card, give orders to their units on a digital copy of the map, and then carry out the result on the table. On own tablets the app does not simulate the opponent; only a pass and play match can have the computer play one side ([docs/PLAY_THE_COMPUTER.md](docs/PLAY_THE_COMPUTER.md)).

## Target devices
The app has to work in desktop browsers **and on Android tablets** (Chrome), in landscape and portrait:
- Touch first: every action works with a single tap. Nothing depends on hover, right-click, double-tap or long-press, and no information is shown only on hover.
- Tap targets are at least 48px (the MUI theme sets `minHeight: 48` on buttons).
- The board SVG scales to the available width (`viewBox`); never give it a fixed pixel size. The page must not scroll sideways.
- Check UI changes at a tablet viewport with touch enabled, e.g. 1280×800 landscape and 800×1280 portrait, as well as desktop.

## Commands
- `npm run dev`: Vite dev server on http://localhost:3000 (polling watcher, because the repo lives on WSL)
- `npm run typecheck`: `tsc --noEmit` (must report 0 errors)
- `npm test`: Vitest in watch mode; use `npx vitest run` for a single run
- `npm run build`: production build to `dist/`, with the service worker (`vite-plugin-pwa`, config in `vite.config.ts`)
- `npm run tablet`: build and serve the production app on the network (port 4173), to test install and offline locally, since the service worker doesn't run in `npm run dev`. Service workers need HTTPS or localhost; see the README for the tablet.

## Deploy
Every push to `main` publishes to GitHub Pages at https://harman440.github.io/m44-sim/ (`.github/workflows/deploy.yml`: typecheck, tests, `vite build --base=/m44-sim/`). The tablet installs the app from there. Keep asset URLs relative to the base (import assets, or use `import.meta.env.BASE_URL`), never a hard-coded `/…` path, or they break under `/m44-sim/`.
- `npm run card-art -- images/<name>.png [maxWidth]`: make a card painting, `src/assets/cards/<name>.webp`, from a large original PNG or JPEG; an image without transparency (any JPEG) has its drawn-in checkerboard background removed, or its white background faded out when its border is all white, or a flat darker grey background (its border all one colour) taken out with a thin soft edge. The originals live in `images/` at the root, which git ignores
- `npm run icons`: regenerate the app icon PNGs from `public/icons/icon.svg`
- `npm run board [-- <part of a name>]`: build the scenarios' board art from their terrain, every board listed in `scripts/boards.json` (its terrain file in `src/data/boards/`, which `scenarios.ts` imports too, the image to write, `drawn`: terrain to draw in code instead of painting it, `river` (with its bridges) or `hedgerow`, and `separateHills`: each hill on its own tile instead of joined into ridges). The base is the empty board (`scripts/board-art/empty-board.webp`, its grid measured at the top of the script) cropped to the edges of its hex grid, the box the app lays the image in, at its full size (2435×1514). Painted terrain comes from the tile library, `scripts/board-art/tiles/<terrain>/`: one hex per image, filling its width, at any resolution; each hex gets one of its terrain's tiles, turned 60° a random number of times (seeded by the hex). A river tile's name starts with the edges its river joins (0 = east, clockwise: `3-0.webp` runs west to east) and it's turned to join the river's edges; a painted bridge is a river tile with `board-art/pieces/bridge.webp` laid across it. A hill next to another hill is joined to it into a ridge (`scripts/joined-hills.mjs`): the plateau runs out through each shared edge (the lakes' outline, `shoreCurves` in `src/boardArt/terrainTiles.mjs`, with a wider neck), the hill tile's cliff ring is unrolled along it, and the plateau and `board-art/textures/grass.webp` are laid across the whole board so they carry over the hex lines; a lone hill keeps its tile. Lakes, and drawn rivers, bridges and hedgerows, come from `src/boardArt/terrainTiles.mjs` (a river flowing through the edges it shares with the next river or bridge hexes, a lake joining its lake neighbours); the frame round the grid is put back over the new hexes. The barbed wire and sandbags pieces aren't part of the board art (they change in the game): they're `src/assets/pieces/*.webp`, drawn on the hex by `BarbedWireArt` and `SandbagsArt`, each image the hex's box with the piece where it sits. Which art each hex gets (tile, turn, river edges, lake edges, ridges) is planned in `src/boardArt/boardPlan.mjs`, shared with the app; the script also writes the app's smaller empty board, `src/assets/board-art/empty-board.webp`

## Architecture
- `src/game-core/`: plain TypeScript game logic with **no React imports**:
  - `BoardManager`: hex grid (with `bothSides`, both sides' units and every sandbag, for the map editor), Axis flip, pathfinding (`calculatePossibleMovesWithPaths`; a hedgerow is only entered from the hex the move starts on, and a unit leaving one moves 1 hex)
  - `Hex`: its terrain (`getType`, and `getTerrain`, the terrain's rules from `data/terrain.ts`), barbed wire (`wire`, from `Scenario.wire`: removable, so not a terrain type; it stops any unit that enters, and a tank that enters removes it, `WIRE_CLEARING_UNIT_TYPES`, kept as `Order.clearedWire` or on the take-ground move for undo), sandbags (`sandbags`: this side's units' only, from `Scenario.sandbags` and Fortify; the enemy's can't be known, so firing asks. `GameSession` clears them when the unit moves off, keeping them on the order or battle edit for undo), board section (`_setSide`), neighbors (offset↔axial coordinates)
  - `GameSession`: owns one player's game (board, command and combat decks and hands, coins, turn flow) and is the only place game rules run. firing from wire costs it a die, `WIRE_FIRE_DICE`; pass and play's `PassAndPlayMatch.removeWire`, and `settleWire`, which takes wire one side removed off the other's board (`wireRemovedByEnemy`) once the orders are carried out, after taking ground and after removing it) and `removeWireAt` (a map edit for wire removed at the table), `removeSandbagsAt` (a map edit taking sandbags off to fix the map), `fortify` (Fortify: in the battle, ordered infantry puts sandbags on its hex instead of firing, a 0-dice `Shot.fortified`, `canFortify`; pass and play's `PassAndPlayMatch.fortify`), the defensive cards (Ni un paso atrás's `ignoreFlags` and Blindaje personal's `ignoreHits` in pass and play's `sufferHits`, told the faces that hit, `armorHits`; Camuflaje's badge, `camouflaged`, kept from turn to turn until the unit moves or battles (`camouflagedUnits`, `isCamouflaged`; the enemy's camouflage: `EnemyUnit.camouflaged`, `ArmyView.camouflaged`, and the fire question `camouflage` when `enemyCamouflage`); Reposicionamiento in pass and play's final phase, `repositioning`/`reposition`; Médico and Mecánico, given to a weakened ordered unit (`AssignRule.weakened`, known only in pass and play), whose `heal` effect `GameSession.heal` applies as the match carries out the orders, a figure's hits per figure, kept on `Assignment.healed`), `drawCard` also draws a second card straight into the hand in a side's first turns with `Scenario.extraDraws` (Pegasus Bridge's Axis; `extraDrawn`), plus `markCloseAssault` and `undoCloseAssaultMark` for the Close Assault card, `hasOrderedUnitFor` for a card with `CombatCard.needsOrdered` (Spotter does nothing without an ordered artillery unit: Órdenes warns)) return `false` and change nothing when they aren't allowed. After each change it publishes an immutable `GameSnapshot`.
  - `CommandCard`: a card's rules as data (sections, fixed or `"chosen"` on play; unit types; number of orders or `"all"`; `perSection` quotas; `onTheMove` extra units that can't fire; `noMove`, `moveBonus`, `maxMove`, `holdShots`; `coinCost` for orders paid in coins; `fireBonus` dice; `closeAssaultOnly` for a card with no orders whose units are marked in the battle; `drawChoice` for cards drawn in the final phase to keep 1 (Preparations: 2); `endOfTurnReward` for Preparations and Refuel; `rewardCard`, the card Refuel gives instead of the draw, from the cards kept out of the deck (`reserve`: Armor Assault, and a Direct from HQ for a side with no armour left; `GameSession` derives which are out, never shuffles them in, and puts them back out once played); `title`, the name on the card face, and `summary`, the few words on a tactic card's face). Everything is derived from the card and the orders given, not stored on units. A unit on a border hex can fill either section's quota; the player picks. `fallbackCard`: a unit-type card with none of its units left orders 1 unit of any type (the snapshot's `activeCard` is the rules in force).

`FireChoice.joined` makes one roll with every unit's dice, each on its own die, `Shot.kinds`, `placed`; the lead shot has `joined`, the others `joinedTo`, all a `group` that "Anular disparo" takes back whole), `suppressiveFire` (Fuego de supresión: a per-shot switch, `FireChoice.suppressive`, rolls the `suppressed` die kind, `suppressive` or `longRangeSuppressive`), `attack` (rolled per marked hex with `attackHex`, before any unit fires; `attackMarks`), `move` (a "Usar …" toggle per move card when ordering, `Order.boostCard`, `boostedLimits` and `MoveRules` in the pathfinding), `changeSection` (Tactician)); no card is played as a reaction (Ambush, Out of Ammo, Pull Back, Out of Fuel and Shell Shortage were taken out in Step 61); the cards are in `data/combatCards.ts`, and `combatDeckFor(scenario, faction)` builds a side's deck from the scenario (each card's `DeckRule` has a `DeckReason`, kept on the card as `CombatCard.reason`, labelled in `DECK_REASON_LABELS` and drawn with `DECK_REASON_ICONS` (`GameIcon`; none for the shared cards) as a badge on the card and before its group's title in the deck; `combatDeckEntries` lists the deck with copies and reasons for the menu): 1 copy of each card the side gets (the shared ones; defensive cards for the defender; offensive ones for the attacker, with 2 of Sin tregua; the rest by its units, Rattenkrieg on a map with more than 8 town hexes, `Scenario.bigGuns` for Cortina de Fuego and `Scenario.airPower` for the air cards' copies). `GameSession` keeps the combat deck and hand (2 to start, at most 3): the cards are played with `pickCard` (`canPlayTogether`, and `combatCardFits`: Tactician needs a card for one section), paid then, and taken back with `cancelCombatCard` until the orders are confirmed (not one whose movement an order used);   - `ai/`: the computer player for a pass and play match (the menu's "Contra el ordenador", `MatchSetup.computer`; `useComputerPlayer` in `MatchView` plays its side at once outside the battle, and `SharedBattleView` drives it in the battle, one thing at a time after `COMPUTER_PAUSE_MS`, its shot up until the person taps "Seguir") ([docs/PLAY_THE_COMPUTER.md](docs/PLAY_THE_COMPUTER.md)): `aiStep(match, side, brain)` does the side's next action through the same session and match actions a person's taps call (`false` when it has nothing to do, or the step is one both players share: the reveal, the movement and collisions, ending the battle), and a `Brain` picks among the options, seeing the enemy only as a player on that side would (`seenEnemies`, from `opponentOf`); `basicBrain` is the very basic one, `standardBrain` the one the app plays (hexes scored by the shots they give against the fire they draw, terrain cover counted; shots by the share of the target they'd destroy; extra orders bought with supplies, `Brain.extraOrder`; combat cards from `combatCardChoice.ts`: the ones it knows, worth more than their supplies, with `Brain.markFor`, `assignTo` and Concentrated Fire's `joined`; a card no unit can take goes back to the hand). `selfPlay.ts` plays a match brain against brain for tests: `aiStep.test.ts` plays every built-in scenario without getting stuck, and `duel.test.ts` (only with `AI_DUEL=1`) measures one brain against another

- `src/data/`: scenarios (terrain, units, board image, starting hand size per side, attacking side, the built-ins in `scenarios.ts`, then the catalog's files, `data/catalog/<id>.json` with their art in `assets/scenarios/<id>.webp`, read by `data/catalog.ts`; a scenario's `name` and `description` are `Localized`), command-card templates, and `fireQuestions.ts`. **`fireQuestions.ts` is where the firing situations live:** each question has its text, options, when it applies (`appliesTo`), how each answer changes the dice (`effect`), and optionally whether an answer rules the shot out (`blocks`, e.g. no line of sight) or adds a reminder for resolving hits (`note`, e.g. sandbags), plus the base-dice and terrain tables (with the official hill rule, `effectiveTerrain`: hill to hill fires as open ground; armour firing from a town loses 2 dice, `FROM_TOWN_FIRE_DICE`), sandbags in the open (`SANDBAGS_IN_THE_OPEN`), `TAKE_GROUND_UNIT_TYPES` and the collision dice (`collisionSteps`). Add new situations there. **`hitRules.ts` says what each die face does to a target** (`faceHits`: a target is only infantry or not, `ShotTarget.infantry`: the infantry symbol hits infantry, the tank symbol any other unit, a grenade always; flags retreat; supplies earn a coin. `enemyTargetKinds` works out whether the enemy starts the scenario with infantry and with other units, `GameSession.targetKinds`, and `TargetKindPicker` only asks when it has both, with "Cambiar" for a reinforcement of the other kind; the session accepts either). ## Conventions
- UI text is in **Spanish and English**; code, identifiers and comments are in English. Every visible string needs both:
  - A component's own text goes in one `TEXT = defineMessages({ es: {…}, en: {…} })` at the top of its file, read with `const t = useMessages(TEXT)`; `defineMessages` makes `en` match `es` key for key. Use functions for texts with numbers, names or plurals. Aria labels, titles and alt texts count.
  - Text that game-core or the data files make (card names and texts, scenario descriptions, fire questions, dice steps, shot notes, reminders) is a `Localized` (`{ es, en }`), shown with `const tr = useTr(); tr(card.name)`. It is saved as both languages, so switching language mid-game changes everything. Write both when you add a card, a question or a scenario.
  - Card names follow the official editions: the Spanish one in `es`, the English one in `en` (Probe, Their Finest Hour, Barrage…).
  - Tests render in Spanish by default (`src/test/setup.ts` sets the browser to Spanish); wrap a render in `SettingsContext.Provider` with `language: "en"` to check English.
- Coins are called **suministros** / **supplies** in the UI (a supply crate icon, `GameIcon name="coins"`); the code keeps "coins".
- UI uses **MUI 9** (`@mui/material`, Emotion) with the theme of the chosen look (`src/looks/`). Use MUI components (`Button`, `Stack`, `Typography`, …) for new UI and style them with `sx`: MUI 9 removed the style-shorthand props on layout components. The SVG board and the card art stay custom.
- Keep rules logic in `game-core/` and cover it with Vitest tests. Components only render and call into game-core.
- Game objects are mutable class instances. Only `GameSession` may change them, and every change must end with it publishing a snapshot; that's what re-renders React. Don't mutate game objects from components. Don't move game logic into a React reducer either: React runs reducers twice in StrictMode, so side effects like `deck.draw()` would happen twice.
- Board: 13×9 offset grid with pointy-top hexes; odd rows have one fewer column and are shifted half a hex. Positions are `{row, col}` and map keys are `"row-col"`. For Axis, positions are flipped and the board image is rotated 180°.
- Sections: left/center/right plus the shared left-center/right-center border hexes (`Hex._setSide`).
- Rules are a loose variant: when a rule is ambiguous, ask instead of assuming official M44.
- The physical table is the source of truth after battle. The app tracks whole units only (no figure counts), and a unit can be moved to any empty hex to mirror a retreat or taking ground. Pass and play is the exception: everything is in the app, and units have figures (`data/figures.ts`, `GameSession.figures`).
- Unit sprites live in `src/assets/units/<allies|axis>/<unit type>.webp|svg` and are mapped in `UnitComponent`. Tank and artillery are placeholder SVGs until real art replaces them.
- Remove debug `console.log` calls before committing.
- Images: use WebP, sized to a few times their display size. Convert new art with `npm run optimize-image -- <file> [maxWidth]`.
- New third-party assets (icons, textures, sounds, fonts) need a licence that allows it, and a line under Credits in the README.
- Animations use `motion` (`motion/react`), only inside the game screens: `GameView` wraps them in `MotionConfig reducedMotion="user"`. Keep motion out of `Menu`, `SettingsDialog` and `App` so it stays out of the first download.
- Bundle: `GameView` is lazy-loaded (`LazyGameView`, preloaded from the menu), and `vite.config.ts` splits react, MUI, motion and three.js into their own chunks (three.js is fetched when the game screen loads, for the 3D dice).
