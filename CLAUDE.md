# m44-sim

A companion web app for playing Memoir '44 with **simultaneous** turns, using a loose house variant rather than the official rules. Each player runs the app for their own faction next to the physical board. They pick a command card, give orders to their units on a digital copy of the map, and then carry out the result on the table. The app does not simulate the opponent or play as an AI.

## Target devices
The app has to work in desktop browsers **and on Android tablets** (Chrome), in landscape and portrait:
- Touch first: every action works with a single tap. Nothing depends on hover, right-click, double-tap or long-press, and no information is shown only on hover.
- Tap targets are at least 48px (the MUI theme sets `minHeight: 48` on buttons).
- The board SVG scales to the available width (`viewBox`); never give it a fixed pixel size. The page must not scroll sideways.
- Check UI changes at a tablet viewport with touch enabled, e.g. 1280×800 landscape and 800×1280 portrait, as well as desktop.

## Commands
- `npm run dev`: Vite dev server on http://localhost:3000 (polling watcher, because the repo lives on WSL)
- `npm run typecheck`: `tsc --noEmit` (must report 0 errors)
- `npm test`: Vitest in watch mode; use `npx vitest run` for a single run
- `npm run build`: production build to `dist/`, with the service worker (`vite-plugin-pwa`, config in `vite.config.ts`)
- `npm run tablet`: build and serve the production app on the network (port 4173), to test install and offline locally, since the service worker doesn't run in `npm run dev`. Service workers need HTTPS or localhost; see the README for the tablet.

## Deploy
Every push to `main` publishes to GitHub Pages at https://harman440.github.io/m44-sim/ (`.github/workflows/deploy.yml`: typecheck, tests, `vite build --base=/m44-sim/`). The tablet installs the app from there. Keep asset URLs relative to the base (import assets, or use `import.meta.env.BASE_URL`), never a hard-coded `/…` path, or they break under `/m44-sim/`.
- `npm run card-art -- images/<name>.png [maxWidth]`: make a card painting, `src/assets/cards/<name>.webp`, from a large original PNG or JPEG; an image without transparency (any JPEG) has its drawn-in checkerboard background removed. The originals live in `images/` at the root, which git ignores
- `npm run icons`: regenerate the app icon PNGs from `public/icons/icon.svg`
- `npm run board -- <tiles.json> <out.webp>`: build a scenario's board art from its terrain (plains, forest and town hexes cut out of the Forêt d'Écouves art; hills, hedgerows, rivers, bridges and lakes drawn as SVG by `scripts/terrain-tiles.mjs`, a river flowing through the edges it shares with the next river or bridge hexes and a lake joining its lake neighbours; on the outer ring the frame is put back over the new hexes); the terrain file in `src/data/boards/` is also what `scenarios.ts` imports

## Architecture
- `src/game-core/`: plain TypeScript game logic with **no React imports**:
  - `BoardManager`: hex grid, Axis flip, pathfinding (`calculatePossibleMovesWithPaths`; a hedgerow is only entered from the hex the move starts on, and a unit leaving one moves 1 hex)
  - `Hex`: terrain properties (river and lake are impassable and hold no unit; a bridge plays like plains), barbed wire (`wire`, from `Scenario.wire`: removable, so not a terrain type; it stops any unit that enters), sandbags (`sandbags`: this side's units' only, from `Scenario.sandbags` and Fortify; the enemy's can't be known, so firing asks. `GameSession` clears them when the unit moves off, keeping them on the order or battle edit for undo), board section (`_setSide`), neighbors (offset↔axial coordinates)
  - `GameSession`: owns one player's game (board, command and combat decks and hands, coins, turn flow) and is the only place game rules run. Actions (`dropUnit`, `undoDrop` and `finishParadrop` for a scenario's paradrop (PARADROP, before the first turn: the player taps where each paratrooper landed on the table), `startFirstTurn`, `pickCard` (with the section, when `cardNeedsSection`) and `unpickCard` (back to the cards before any order is given), `issueOrder` (with an order slot, when a unit could take more than one), `undoLastOrder`, `commitOrders` (locks the orders and goes straight to MOVEMENT), `startBattle`, `endBattle` (which draws the command card), `drawCard` (only for an old save; a single card is kept at once; `drawAgain` swaps it once, Gamble; Probe draws 2 and `keepCard` keeps 1), `endTurn`, plus the map sync `removeUnit` (with the experimental `artilleryCrew` rule, `GameSetup.artilleryCrew`, a menu "Ajustes" switch, saved: artillery removed in the final phase leaves an infantry unit on its hex, `leavesCrew`, the edit's `replacement`), `relocateUnit` and `undoBattleEdit` (`canEditMap`: in the final phase, and in Órdenes before any order or mark, to fix a map that doesn't match the table; those edits are `beforeOrders` and can't be undone after the orders), `rollReinforcements` and `placeReinforcement` for the Reinforcements card (the app rolls the die in the final phase and puts the unit on the cross; the new unit is an `add` battle edit), and firing: `fireTargetsFor` (the hexes a unit can fire at), `fireAt` (at a hex picked on the map; `fire` takes the questionnaire's answers directly), `fireCollision`, `undoShot`, `canTakeGround`/`takeGround`/`undoTakeGround` (after a close assault with a hit or a flag, armour, or infantry with Fragor del combate, takes ground: it moves to the target's hex as a battle edit and gets one more shot, adjacent only; `Shot.tookGround`, derived in the summary), `keepResults` (apply fewer results than were rolled: `Shot.kept`, read with `appliedFaces`), `skipUnmovedFire`, `removeWire` (infantry on barbed wire removes it instead of firing: a 0-dice `Shot` with `removedWire`; firing from wire costs it a die, `WIRE_FIRE_DICE`) and `removeWireAt` (a map edit for wire removed at the table), `placeSandbagsAt`/`removeSandbagsAt` (map edits: Fortify's sandbags on one of the `fortifiable` units, or taking them off to fix the map), `drawCard` also draws a second card straight into the hand in a side's first turns with `Scenario.extraDraws` (Pegasus Bridge's Axis; `extraDrawn`), plus `markCloseAssault` and `undoCloseAssaultMark` for the Close Assault card, `blockShot` for a shot the opponent's card stops (Out of Ammo…: "Bloqueado por el rival" in the Fire dialog, `Shot.blocked`, no roll and no more shots this turn), `hasOrderedUnitFor` for a battle card with `CombatCard.needsOrdered` (Spotter and Reposition need an ordered artillery unit)) return `false` and change nothing when they aren't allowed. After each change it publishes an immutable `GameSnapshot`.
  - `CommandCard`: a card's rules as data (sections, fixed or `"chosen"` on play; unit types; number of orders or `"all"`; `perSection` quotas; `onTheMove` extra units that can't fire; `noMove`, `moveBonus`, `maxMove`, `holdShots`; `coinCost` for orders paid in coins; `fireBonus` dice; `closeAssaultOnly` for a card with no orders whose units are marked in the battle; `drawChoice` for cards drawn in the final phase to keep 1 (Probe: 2); `endOfTurnReward` for Preparations; `title`, the name on the card face, and `summary`, the few words on a tactic card's face). The house decks are in `data/commandCards.ts`: `commandDeckFor(scenario, faction)` builds a side's 25 cards, the shared ones plus 4 for the unit types it has; `GameSession.commandCards` and `combatCards` are the whole decks (the deck visualizer shows them, grouping copies by `templateId`). Card names follow the official Spanish edition where we found them (Batida, La Hora de la Verdad, …) and the English edition in English; a few are house names (Vanguardia).
  - `orderRules.ts`: pure functions that apply a card: which order slots a unit can take (a card order, in a section for quota cards, or on the move), its move limits, the orderable units and the orders left. Everything is derived from the card and the orders given, not stored on units. A unit on a border hex can fill either section's quota; the player picks. `fallbackCard`: a unit-type card with none of its units left orders 1 unit of any type (the snapshot's `activeCard` is the rules in force).
  - `combatCard.ts`: the `CombatCard` type (cost, phase `"order"` or `"battle"`, an optional `marker` rule for hexes to mark on the orders map, checked in `markerRules.ts` and set with `markHex`/`undoMarker`, and an optional `tableReminder` for the final phase, and an optional `effect` the app applies: `diceBonus` (asked in the fire questions, `combatBonusFor`), `attack` (rolled per marked hex with `attackHex`, before any unit fires), `move` (the "Usar …" toggle when ordering, `boostedLimits` and `MoveRules` in the pathfinding), `changeSection` (Tactician) or `ambush` (Emboscada: playing it opens `AmbushDialog`, where the player taps their unit attacked in close assault and then the attacker, as in `FireAim`; `GameSession.ambushAt` rolls it as `ambush`, an `AmbushShot` kept apart from the orders' shots, with `undoAmbush`/`keepAmbushResults`)); the cards are in `data/combatCards.ts`, and `combatDeckFor(scenario, faction)` builds a side's deck from the scenario (each card's `DeckRule` has a `DeckReason`, kept on the card as `CombatCard.reason`, labelled in `DECK_REASON_LABELS` and drawn with `DECK_REASON_ICONS` (`GameIcon`; none for the shared cards) as a badge on the card and before its group's title in the deck; `combatDeckEntries` lists the deck with copies and reasons for the menu): 1 copy of each card the side gets (the shared ones; defensive cards for the defender; offensive ones for the attacker, with 2 of Sin tregua; the rest by its units, the enemy's armour, Rattenkrieg on a map with more than 8 town hexes, `Scenario.bigGuns` for Cortina de Fuego and `Scenario.airPower` for the air cards' copies). `GameSession` keeps the combat deck and hand (2 to start, at most 3): an order card is played with `pickCard` (only when `combatCardFits`: Tactician needs a card for one section), a battle card with `playBattleCombatCard` (one per battle), both paid when played; the final phase draws one with `chooseReward("combatCard")` or `drawCombatCard` (Preparations), and `discardCombatCard` when the hand is over 3. **Test mode** (`GameSetup.testMode`, the menu's "Modo prueba" switch, `GameSession.testMode`, saved): the hand starts with one of every combat card (`allCombatCards`), there's no hand limit, played cards come back to the hand at the end of the turn, and each turn starts with at least `TEST_MODE_COINS`
  - `Unit` (`elite`, from `Scenario.elite`: a scenario's badge; it moves its whole move and still fires, drawn as a star badge), `Order` (its shots, the section quota it used and whether it's on the move; `canFire` is `shots > 0`; an order's index identifies it for the turn), `Deck`
  - `position.ts`: `samePosition`, `positionKey` ("row-col") and `includesPosition`; use them rather than comparing rows and columns by hand
  - `dice.ts` (three dice, `DieKind` and `SIDES_OF`: the Memoir '44 battle die: 2 infantry, tank, grenade, supply (the star of the official die), flag; the house 8-sided long-range die (2 tanks, 3 infantry, flag, 2 supplies), a per-game setting (`GameSetup.longRangeDie`, `GameSession.longRangeDie`) rolled at targets that aren't adjacent; and the attack cards' die, with a second grenade for the supply. `ShotTarget.die` says which was rolled) and `turnSummary.ts` (what each order means for the battle, and the firing order: units that didn't move fire first, moved units wait)
  - `turnLog.ts`: `recordTurn` turns a finished turn into a plain-JSON `TurnRecord` (card, orders, shots, map edits); `GameSession.endTurn` appends it to the log in the snapshot and save
  - `fireRules.ts`: engine for the "how many dice?" questionnaire (next question, adding up the dice)
  - `fireTargets.ts`: `hexDistance`, `hasLineOfSight` (blocked by `SIGHT_BLOCKING_TERRAIN` or this side's units in between; along an edge only if both hexes block) and `fireTargets`, the hexes in range with their dice (artillery fires without line of sight: `checksLineOfSight` in `unit.ts`); the map answers the distance and terrain questions (`mapAnswers`)
  - `rollResult.ts`: `readRoll` reads a roll against its target (hits, retreats, coins) with the rules in `data/hitRules.ts`
  - `coins.ts`: `turnCoins` works out the turn's coin ledger from its orders (extra orders, Finest Hour), shots (stars), final-phase choice and changes by hand, so undoing an order or shot gives its coins back; `GameSession` keeps the coins at the start of the turn plus `adjustCoins`/`undoCoinAdjustment` and `chooseReward` (2 coins or a combat card, taken once: the view lets the player switch between them and confirm). Costs are in `data/coinRules.ts`
- `src/data/`: scenarios (terrain, units, board image, starting hand size per side, attacking side, the Reinforcements card's table of units per die face), command-card templates, and `fireQuestions.ts`. **`fireQuestions.ts` is where the firing situations live:** each question has its text, options, when it applies (`appliesTo`), how each answer changes the dice (`effect`), and optionally whether an answer rules the shot out (`blocks`, e.g. no line of sight) or adds a reminder for resolving hits (`note`, e.g. sandbags), plus the base-dice and terrain tables (with the official hill rule, `effectiveTerrain`: hill to hill fires as open ground; armour firing from a town loses 2 dice, `FROM_TOWN_FIRE_DICE`), sandbags in the open (`SANDBAGS_IN_THE_OPEN`), `SIGHT_BLOCKING_TERRAIN`, `TAKE_GROUND_UNIT_TYPES` and the collision dice (`collisionSteps`). Add new situations there. **`hitRules.ts` says what each die face does to a target** (`faceHits`: a target is only infantry or not, `ShotTarget.infantry`: the infantry symbol hits infantry, the tank symbol any other unit, a grenade always; flags retreat; supplies earn a coin. `enemyTargetKinds` works out whether the enemy starts the scenario with infantry and with other units, `GameSession.targetKinds`, and `TargetKindPicker` only asks when it has both, with "Cambiar" for a reinforcement of the other kind; the session accepts either). The numbers start from the official M44 values and are meant to be tuned to the house rules.
- `src/types/`: shared types and enums (`TurnPhase`, `HexType`, `Side`, `Position`, `Faction`/`GameSetup`, …)
- `src/App.tsx`: creates the `GameSession` and shows `Menu` (a list of scenarios with a small thumbnail; tapping one opens a panel beside it (under it in portrait) with its description, its map with the starting units (`ScenarioPreview`, lazy-loaded since `Board` brings in the game screen's code, turned round for the Axis) and `ScenarioDetails`, a table of the two sides whose column headers pick the side: role, starting command cards and the size of the combat deck, each row explained behind an "i"; tapping a side's combat deck opens `CombatDeckDialog` (lazy-loaded), its cards grouped by why the side gets them; the test rules (8-sided die, Modo prueba) are in the menu's "Ajustes", passed into `SettingsDialog` as children; "Reglamento" opens the rule book) or `GameView`. It saves the session after every change and resumes it on load, so a reload or the tablet dropping the tab doesn't lose the game; "Salir" forgets the save.
- Rule book: `components/RuleBookDialog.tsx` (lazy-loaded), opened from the menu's "Reglamento" and the game's "Menú": a tutorial, a page per phase of the turn, and the house rules beside the official ones (the 2004 rulebook and the base game's cards), grouped. Its text is `data/ruleBook.ts`; **when a rule changes, change its text there too** (the numbers come from the data files).
- `src/storage.ts`: everything kept in `localStorage` (the last setup and the game in progress). Reads and writes fail quietly, and an unreadable save is dropped.
- Saving: `game-core/saveGame.ts` turns the session into a plain-JSON `SavedGame` (cards by id, units by index so orders and battle edits keep their references) and reads it back, throwing on anything it can't match; `GameSession.save()`/`restore()` call it. **When you add state to `GameSession`, add it to `SessionState` and `SavedGame` too**, and bump `SAVE_VERSION` when the shape changes: older saves are dropped, not migrated.
- `src/looks/`: the three visual looks the player picks in "Ajustes" (`looks.ts`: colours, fonts, shape, texture per look) and `theme.ts`, which builds the MUI theme and the `--m44-*` CSS variables from a look. **Style custom CSS with the `--m44-*` variables, never fixed colours**, so it works in every look. Bundled fonts are imported in `looks/fonts.ts`.

## Conventions
- UI text is in **Spanish and English**; code, identifiers and comments are in English. Every visible string needs both:
  - A component's own text goes in one `TEXT = defineMessages({ es: {…}, en: {…} })` at the top of its file, read with `const t = useMessages(TEXT)`; `defineMessages` makes `en` match `es` key for key. Use functions for texts with numbers, names or plurals. Aria labels, titles and alt texts count.
  - Text that game-core or the data files make (card names and texts, scenario descriptions, fire questions, dice steps, shot notes, reminders) is a `Localized` (`{ es, en }`), shown with `const tr = useTr(); tr(card.name)`. It is saved as both languages, so switching language mid-game changes everything. Write both when you add a card, a question or a scenario.
  - Card names follow the official editions: the Spanish one in `es`, the English one in `en` (Probe, Their Finest Hour, Barrage…).
  - Tests render in Spanish by default (`src/test/setup.ts` sets the browser to Spanish); wrap a render in `SettingsContext.Provider` with `language: "en"` to check English.
- Coins are called **suministros** / **supplies** in the UI (a supply crate icon, `GameIcon name="coins"`); the code keeps "coins".
- UI uses **MUI 9** (`@mui/material`, Emotion) with the theme of the chosen look (`src/looks/`). Use MUI components (`Button`, `Stack`, `Typography`, …) for new UI and style them with `sx`: MUI 9 removed the style-shorthand props on layout components. The SVG board and the card art stay custom.
- Keep rules logic in `game-core/` and cover it with Vitest tests. Components only render and call into game-core.
- Game objects are mutable class instances. Only `GameSession` may change them, and every change must end with it publishing a snapshot; that's what re-renders React. Don't mutate game objects from components. Don't move game logic into a React reducer either: React runs reducers twice in StrictMode, so side effects like `deck.draw()` would happen twice.
- Board: 13×9 offset grid with pointy-top hexes; odd rows have one fewer column and are shifted half a hex. Positions are `{row, col}` and map keys are `"row-col"`. For Axis, positions are flipped and the board image is rotated 180°.
- Sections: left/center/right plus the shared left-center/right-center border hexes (`Hex._setSide`).
- Rules are a loose variant: when a rule is ambiguous, ask instead of assuming official M44.
- The physical table is the source of truth after battle. The app tracks whole units only (no figure counts), and a unit can be moved to any empty hex to mirror a retreat or taking ground.
- Unit sprites live in `src/assets/units/<allies|axis>/<unit type>.webp|svg` and are mapped in `UnitComponent`. Tank and artillery are placeholder SVGs until real art replaces them.
- Remove debug `console.log` calls before committing.
- Images: use WebP, sized to a few times their display size. Convert new art with `npm run optimize-image -- <file> [maxWidth]`.
- New third-party assets (icons, textures, sounds, fonts) need a licence that allows it, and a line under Credits in the README.
- Animations use `motion` (`motion/react`), only inside the game screens: `GameView` wraps them in `MotionConfig reducedMotion="user"`. Keep motion out of `Menu`, `SettingsDialog` and `App` so it stays out of the first download.
- Bundle: `GameView` is lazy-loaded (`LazyGameView`, preloaded from the menu), and `vite.config.ts` splits react, MUI, motion and three.js into their own chunks (three.js is fetched when the game screen loads, for the 3D dice).

## MCP servers (`.mcp.json`)
- `playwright`: drive the dev server, click through a turn and take screenshots to check UI changes. It runs headless Chromium (`--browser chromium --headless`); if the browser is missing, run `npx playwright install chromium`.
- `context7`: up-to-date docs for React 19, Vite 7 and Vitest
- `chrome-devtools`: console errors and performance traces of the SVG board

## Workflow
Personal project: commit straight to `main` with conventional-commit messages (`feat:`, `fix:`, `refactor:`, `test:`, `chore:`). No PRs or reviews. Before committing, run `npm run typecheck` and `npx vitest run`, and for UI changes check the flow in the browser.
